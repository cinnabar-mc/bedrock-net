# Go batch oracle

This small helper emits synthetic compressed batches through Cinnabar's pinned
Gophertunnel codec. It uses no game assets, accounts or external servers.

From this directory, regenerate the Rust fixture:

```sh
go run . > ../../tests/fixtures/go_batches.rs
cargo fmt --all --manifest-path ../../Cargo.toml
```

The module pin identifies the behavior baseline. Update it deliberately when
reviewing upstream compatibility changes, then inspect any fixture differences.

The `cmd/login-check` helper verifies synthetic offline requests with the same
Go pin and returns a signed server handshake plus an independent P-384 key
derivation. It reads bounded fixture JSON from stdin and requires loopback
metadata, so no account credentials or external hosts are needed.

Its separate `identity_token` input compares synthetic player identity projection
through the pinned Go Login owner. The Rust test supplies the original claims;
this mode tests field/UUID compatibility and does not establish issuer trust.

Build `go build -o ../../target/login-check.exe ./cmd/login-check` and set
`BEDROCK_NET_LOGIN_ORACLE` to that executable before running
`cargo test --locked -p bedrock-net --features login`.

`cmd/pack-delivery-check` exposes the same pin's exported delivery defaults/cap
and actual resource.ChunkCount results for bounded caller-supplied synthetic
JSON cases. It copies no reference table. Build it, then provide
`BEDROCK_NET_PACK_DELIVERY_ORACLE` when testing bedrock-client; CI does this
for the workspace tests. This checks identified Go policy, not vanilla behavior.

`cmd/builtin-packs` regenerates the client's version-bound built-in pack catalog:

```sh
go run -mod=readonly ./cmd/builtin-packs ../../crates/bedrock-client/data/builtin-packs.json
```

It reads the complete exemption list from the checksum-pinned module selected by
this directory's `go.mod`, checks that the compiled Go dependency is identical,
and verifies every identity against `minecraft.IsBuiltinResourcePack`. The
protocol and baseline version come from that same dependency. CI regenerates
the catalog and checks the committed bytes; update the Go module pin and this
catalog together. Rust also checks the catalog's protocol and module binding.

`go run . serve` answers length-prefixed JSON requests on stdin (batch decode/encode
with compression and key, cipher checksums, Login build/parse) for `tests/oracle.rs`;
build it and set `BEDROCK_NET_GO_ORACLE`. `cmd/interop-server SCENARIO` accepts one
loopback client through `minecraft.Listen` or a scripted packet order, for the probe's
interop tests under `BEDROCK_NET_GO_INTEROP`.

`bench/` holds gophertunnel benchmarks over `testdata/bench`, named to pair with the
criterion benches; `tools/bench-compare` joins the two. `cmd/bench-inputs` regenerates
those synthetic inputs.

`clientdata` reflects the selected `login.ClientData` types and checks the Rust
metadata schema plus Go Unicode, x/text locale and JSON nesting tables. Ordinary
`go test ./...` checks generated bytes without writing them. To deliberately
regenerate and review a changed baseline, run:

```sh
go test ./clientdata -run 'TestNativeClientData(Schema|SemanticData)$' -update-native-client-data-schema -update-native-client-data-semantics
```

Use this module's selected Go version and dependencies; changing a generated
source pin alone does not update its data or establish behavioral compatibility.

`cmd/accepting-client-data` regenerates the accepting login locale registries and
Unicode letter ranges. From this directory, run:

```sh
GOTOOLCHAIN=go1.26.1 go run -mod=readonly ./cmd/accepting-client-data ../../src/login/accepting/client_data
```

The generator requires Go 1.26.1, Unicode 15.0.0 and the checksum-pinned
`golang.org/x/text v0.35.0` dependency without a replacement. It locates the module
through `go list -m -json`, so it needs no fixed module-cache path. CI regenerates
both files and fails if their committed bytes differ. Review any baseline change
and preserve the generated files' Go license notices.

`go run . offline-fixtures` emits 55 deterministic synthetic offline Login
requests and the selected Go parser's actual results. `go test -run
TestOfflineFixtures .` checks the decisions, key selection and repeatable bytes.
All fixed keys and signatures belong only to these test fixtures.

The RPC operations `offline_shapes`, `offline_curve_fixtures` and
`offline_encoding_fixtures` provide synthetic header, signing-key and compact
encoding controls. Each helper checks its expected results with the pinned Go
parser before returning the cases. Run `go test ./...` to check the inventories.

`offline_json_contexts` checks duplicate fields, numeric overflow and nesting
across standard JSON and JOSE decoding. `resolve_udp` checks one supplied UDP
address with the local Go resolver; resolver-dependent results are not fixtures.

`jose_headers` compares protected-header shapes across unverified identity,
metadata, legacy chain, authenticated metadata and server-handshake roles.

`offline_time_fixtures` supplies deterministic caller-UTC NumericDate controls.
Large-date cases also anchor actual Login Parse; exact one-minute boundaries use
the pinned JWT validator with the returned fixed UTC, without reading a test clock.
